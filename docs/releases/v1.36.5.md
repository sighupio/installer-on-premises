# On Premises installer release v1.36.5

Welcome to the latest release of `on-premises` installer of [`SIGHUP Distribution`](https://github.com/sighupio/distribution) maintained by SIGHUP by ReeVo team.

This release adds support for Kubernetes versions 1.36.5, 1.35.9, and 1.34.12. It updates etcd to v3.6.15 and adds containerd 2.3 support for Kubernetes 1.36.

## Breaking Changes 💔

- Dropped support for Kubernetes versions below `1.34`: `1.28`, `1.29`, `1.30`, `1.31`, `1.32` and `1.33` have been removed. Clusters running one of those versions must be upgraded to at least `1.34.4` before using this release.
- Kubeadm configuration API: the roles now render the kubeadm configuration exclusively with `kubeadm.k8s.io/v1beta4`. This changes `extraArgs` from a map to a list of `name`/`value` entries and replaces `apiServer.timeoutForControlPlane` with `InitConfiguration.timeouts.controlPlaneComponentHealthCheck`. `v1beta3` is deprecated, kubeadm `1.36` already warns when it is used.
- Containerd configuration migration: containerd 2.3 uses config version 4, the split CRI images/runtime plugins, and `certs.d/hosts.toml` for registry mirrors. Custom containerd configurations, plugins, runtime integrations, and registry mirrors that rely on the v1.x plugin paths or deprecated fields must be migrated and validated before upgrading a node.

## Bug Fixes 🐛

- [[#174](https://github.com/sighupio/installer-on-premises/pull/174)] Fix kube-control-plane role to accept usernames with spaces and create the users' kubeconfig on just one node instead of all the masters.

## New features 🌟

- Add Kubernetes 1.36 support, including kubeadm v1beta4 configuration for control-plane and worker nodes.
- Add support for Debian 13
- [[#181](https://github.com/sighupio/installer-on-premises/pull/181)] Add `oidc_extra_audiences` to `kube-control-plane` to support multiple OIDC audiences via `AuthenticationConfiguration`.

## Update Guide 🦮

### Automatic upgrade using furyctl

To update using furyctl, follow this [documentation](https://docs.sighup.io/docs/installation/upgrades).

### Manual update

> NOTE: Each on-premises environment can be different, always double-check before updating components.

1. Update SD if applicable (see the [SD release notes](https://github.com/sighupio/distribution/tree/main/docs/releases))
2. Update the cluster using playbooks, see the examples in this repository to know more.
